# Feature package

`tanbun.feature` は、機能をドメインモデル、ユースケース、DB 操作、API、テストごと
まとめて配置するためのパッケージです。機能を削除するとき、そのディレクトリを
取り除けば大部分が消える構成を目指します。

## 配置の基準

- 各機能の `domain` はドメインモデルを持ち、DB 操作を含めません。
- DB や外部システムへのアクセスは各機能の `repo` に置きます。
- テストは対象コードと同じ機能ディレクトリに置きます。
- 複数機能を組み合わせる処理も、それを提供する機能側に置きます。
- すべてのfeatureが利用する基礎的な型や例外は、直下の `domain` に置きます。
- すべてのfeatureのDB操作で利用する土台は、直下の `repo` に置きます。
- 直下の `domain` と `repo` は個別のfeatureには依存させません。
- feature間の依存は許可しますが、循環依存は禁止します。
- 複数featureのrouterは、feature内部ではなくAPIルートで組み立てます。
- 知識グラフ固有の型や変換処理は `tanbun/graph` に置きます。

旧 `tanbun.integration` と `tanbun.shared` は使用しません。共有が必要になった処理も、
まず所有する機能を決め、真に機能非依存なものだけを直下の `domain` または
`repo` に置きます。
